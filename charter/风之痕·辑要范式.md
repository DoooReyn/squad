# 风之痕·辑要范式

> *"每一次提交，都是风中留下的痕迹。历史由一个个印记串联，清晰可读，方为永恒。"*
> —— 吟游诗人 小柯

> 本范式采用 **Conventional Commits** 规范，确保 Git 历史清晰、可追溯。

---

## 核心原则

> *"好的提交信息应该回答：做了什么，为什么做。"*

1. **原子化提交** — 每次提交只做一件事
2. **清晰即正义** — 信息应该让人一目了然
3. **历史即文档** — 提交历史本身就是项目文档
4. **杜绝 WIP** — 不提交未完成的工作

---

## Commit Message 格式

### 基本结构

```
<类型>(<范围>): <简短描述>

<详细描述>

<页脚>
```

### 类型（Type）

| 类型 | 图标 | 说明 | 示例 |
|------|------|------|------|
| `feat` | ✨ | 新功能 | 添加英雄系统 |
| `fix` | 🐛 | Bug 修复 | 修复战斗数值错误 |
| `docs` | 📚 | 文档更新 | 更新 README |
| `style` | 💄 | 代码风格（不影响功能） | 统一缩进格式 |
| `refactor` | ♻️ | 重构（不是新功能也不是修复） | 重构状态机 |
| `perf` | ⚡ | 性能优化 | 优化渲染性能 |
| `test` | ✅ | 测试相关 | 添加单元测试 |
| `build` | 📦 | 构建系统或外部依赖 | 更新依赖版本 |
| `ci` | 👷 | CI 配置文件和脚本 | 添加 GitHub Actions |
| `chore` | 🔧 | 其他不修改 src 或 test 的更改 | 更新配置文件 |
| `revert` | ⏪ | 回退提交 | Revert "feat: xxx" |

### 范围（Scope）

范围用于指定提交影响的模块，应根据项目目录结构定义。

```bash
# 示例范围（根据项目实际情况调整）
framework  # 框架核心
ui         # UI 模块
battle     # 战斗系统
data       # 数据模块
config     # 配置文件
```

### 简短描述（Subject）

- 使用**现在时态**："添加" 而非 "添加了"
- 首字母**小写**
- 结尾**不要句号**
- 限制在 **50 字符以内**

```
✅ 好的：
feat(battle): 添加英雄攻击系统
fix(ui): 修复血条显示错误
docs(readme): 更新安装说明

❌ 坏的：
feat(battle): 添加了英雄攻击系统
Feat(battle): Add hero attack system
fix(ui): 修复血条显示错误。
```

### 详细描述（Body）

- 列出**做了什么**和**为什么做**
- 每行限制在 **72 字符以内**
- 使用**现在时态**和**祈使句**

```
✅ 好的：
feat(battle): 添加英雄攻击系统

- 实现 Hero 类的 attack 方法
- 添加伤害计算逻辑
- 支持暴击和闪避判定

优化了伤害计算的效率，减少了不必要的循环。

❌ 坏的：
feat(battle): 添加英雄攻击系统

我添加了一个攻击方法，然后还有伤害计算，
还有暴击什么的。
```

### 页脚（Footer）

- 用于记录**Breaking Changes**和**关联 Issue**
- Breaking Changes 以 `BREAKING CHANGE:` 开头
- 关联 Issue 使用 `Closes` 或 `Resolves` 关键字

```
feat(battle): 重构伤害计算系统

BREAKING CHANGE: 伤害计算公式已完全重写，旧配置不再兼容。

Closes #123
```

## 完整示例

### 示例 1：新功能

```
feat(battle): 添加英雄技能系统

- 实现 Skill 基类和多个子类
- 添加技能冷却机制
- 实现技能释放的目标选择

技能系统采用组件化设计，方便后续扩展新的技能类型。

Closes #45
```

### 示例 2：Bug 修复

```
fix(ui): 修复血条在战斗结束后不消失的问题

血条组件未正确监听战斗结束事件，导致血条残留。
现已添加 onBattleEnd 生命周期处理。

Fixes #89
```

### 示例 3：重构

```
refactor(framework): 统一事件总线接口

将各模块的事件发送统一到 EventManager，
移除了分散的 emit 函数。

BREAKING CHANGE: 模块发送事件需使用 EventManager.emit()
```

### 示例 4：文档更新

```
docs(readme): 更新项目启动指南

添加了 Cocos Creator 版本要求和依赖安装步骤。
```

## 分支命名规范

### 主分支

| 分支 | 说明 |
|------|------|
| `main` | 主分支，始终保持可发布状态 |
| `develop` | 开发分支（可选） |

### 功能分支

```
feat/<功能名>
```

```
feat/battle-system
feat/hero-skill
feat/ui-framework
```

### 修复分支

```
fix/<问题描述>
```

```
fix/blood-bar-bug
fix/login-crash
```

### 重构分支

```
refactor/<模块名>
```

```
refactor/event-bus
refactor/state-machine
```

### 热修复分支

```
hotfix/<版本号>-<描述>
```

```
hotfix/v1.0.1-crash-fix
hotfix/v1.2.0-memory-leak
```

## 分支工作流

### 功能开发流程

```bash
# 1. 从 main 创建功能分支
git checkout main
git pull origin main
git checkout -b feat/battle-system

# 2. 开发并提交（遵循本范式）
git add .
git commit -m "feat(battle): 添加战斗系统"

# 3. 推送到远程
git push origin feat/battle-system

# 4. 创建 Pull Request
# 5. 代码审查通过后合并到 main
# 6. 删除功能分支
git branch -d feat/battle-system
```

### 紧急修复流程

```bash
# 1. 从 main 创建 hotfix 分支
git checkout main
git checkout -b hotfix/v1.0.1-crash-fix

# 2. 修复并提交
git commit -m "fix: 修复游戏崩溃问题"

# 3. 合并到 main 和 develop（如有）
git checkout main
git merge hotfix/v1.0.1-crash-fix

# 4. 打标签
git tag -a v1.0.1 -m "修复崩溃问题"

# 5. 删除 hotfix 分支
git branch -d hotfix/v1.0.1-crash-fix
```

## 合并规范

### 允许的合并方式

| 方式 | 使用场景 |
|------|----------|
| **Merge Commit** | 功能分支合并到 main（保留完整历史） |
| **Squash and Merge** | 小型修复、清理 WIP 提交 |
| **Rebase and Merge** | ❌ 禁止使用（会丢失历史） |

### Pull Request 规范

- PR 标题遵循 Commit Message 格式
- PR 描述应包含：
  - **做了什么**：变更内容概述
  - **为什么做**：变更原因
  - **如何测试**：测试步骤
  - **截图/录屏**（如有 UI 变更）

```
PR 标题：feat(battle): 添加英雄技能系统

描述：
实现了英雄技能系统，包括技能冷却、目标选择等功能。

变更内容：
- 新增 Skill 基类
- 实现 5 个具体技能
- 添加技能 UI

测试步骤：
1. 进入战斗场景
2. 点击技能按钮
3. 验证技能效果和冷却

截图：
[技能效果截图]
```

## 版本号规范

遵循 **语义化版本（SemVer）**：

```
<主版本>.<次版本>.<修订版>

例如：1.2.3
```

| 版本号 | 规则 | 示例 |
|--------|------|------|
| **主版本** | 不兼容的 API 变更 | 1.0.0 → 2.0.0 |
| **次版本** | 向下兼容的功能新增 | 1.0.0 → 1.1.0 |
| **修订版** | 向下兼容的 Bug 修复 | 1.0.0 → 1.0.1 |

### 预发布版本

```
1.0.0-alpha.1
1.0.0-beta.1
1.0.0-rc.1
```

## 禁止事项

### ❌ 禁止的提交行为

| 行为 | 说明 |
|------|------|
| 提交调试代码 | console.log、debugger 等应移除 |
| 提交敏感信息 | API 密钥、密码、token 等 |
| 提交构建产物 | node_modules、build、temp 等 |
| 混合多种变更 | 一个提交包含多个不相关的修改 |
| 提交未完成代码 | 留下 TODO 或 FIXME |
| 提交格式化变更 | 与功能变更混在一起 |

### ❌ 禁止的 Commit Message

```
# 太模糊
update
fix bug
modify
done
修改文件

# 不规范
add feature
fix bug for battle
UPDATE README
Fix#123

# 包含敏感信息
fix: add api key 12345
```

## 提交守护机制

> *"本团队采用自动化工具守护提交规范，确保每一行代码都符合宪章要求。"*

### 工具链

| 工具 | 职责 |
|------|------|
| **Husky** | Git Hooks 管理，在特定时机触发检查 |
| **Commitlint** | 检查 Commit Message 是否符合规范 |
| **lint-staged** | 只检查暂存文件，提升性能 |
| **ESLint** | 代码质量检查 |
| **Prettier** | 代码格式化 |

### 工作流程

```bash
git add .
git commit -m "feat: 添加新功能"
```

**自动执行：**
1. ✅ **pre-commit hook**：lint-staged → ESLint → Prettier
2. ✅ **commit-msg hook**：commitlint 检查格式

**任一环节失败，提交将被拦截！**

### 配置文件

```bash
# 项目根目录的配置文件
├── commitlint.config.js    # Commitlint 规则配置
├── eslint.config.mjs       # ESLint 规则配置（Flat Config）
├── .prettierrc             # Prettier 格式化规则
├── .lintstagedrc.json      # lint-staged 检查配置
└── .husky/                 # Git Hooks 脚本
    ├── pre-commit          # 提交前检查
    └── commit-msg          # 提交信息检查
```

### 安装命令

```bash
# 安装依赖
npm install -D husky @commitlint/config-conventional @commitlint/cli lint-staged

# 初始化 Husky
npx husky init

# 安装完成后，守护机制自动生效
```

### 配置示例

#### commitlint.config.js

```javascript
module.exports = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'type-enum': [
      2,
      'always',
      ['feat', 'fix', 'docs', 'style', 'refactor', 'perf', 'test', 'build', 'ci', 'chore', 'revert'],
    ],
    'type-case': [2, 'always', 'lower-case'],
    'type-empty': [2, 'never'],
    'subject-empty': [2, 'never'],
    'subject-full-stop': [2, 'never', '.'],
    'header-max-length': [2, 'always', 100],
  },
};
```

#### .lintstagedrc.json

```json
{
  "*.ts": [
    "eslint --fix",
    "prettier --write"
  ],
  "*.{ts,json,md}": [
    "prettier --write"
  ]
}
```

#### .husky/commit-msg

```bash
#!/bin/sh
npx --no -- commitlint --edit $1
```

#### .husky/pre-commit

```bash
#!/bin/sh
npx lint-staged
```
