## 核心原则

> *"冒险团不在牢笼中建设，而在旷野中开拓。目录结构亦然，随需求而生，随成长而变。"*

1. **演进式建设** — 从最简单的结构开始，随需求增长
2. **职责单一** — 每个目录有清晰的职责定位
3. **命名统一** — 遵循「风之语·命名法典」的 kebab-case 规范
4. **层次节制** — 目录层级不超过 3-4 层
5. **因地制宜** — 根据项目实际调整，不拘泥于形式

## 建设原则

### 何时创建新目录？

当出现以下情况时，考虑创建新目录：

| 情况 | 行动 |
|------|------|
| 文件数量超过 5-10 个 | 考虑分类 |
| 出现明显不同的功能模块 | 创建独立目录 |
| 多个文件共享某种属性 | 按属性分类 |
| 目录层级超过 4 层 | 重新组织结构 |

### 如何命名目录？

遵循「风之语·命名法典」：

- **目录名**：kebab-case（小写 + 连字符）
- **单复数**：优先使用复数形式（如 `panels/`、`utils/`）
- **描述性**：名称应清楚表达目录内容

```typescript
// ✅ 好的命名
assets/
├── framework/
├── ui-panels/
├── battle-system/
└── utils/

// ❌ 坏的命名
assets/
├── Framework/
├── uiPanel/
├── BattleSystem/
└── util/
```

### 何时重构目录？

当出现以下信号时，考虑重构：

- 新增文件时不知道该放哪里
- 经常需要在多个目录间跳转
- 目录名称不能准确描述其内容
- 同类文件散落在不同位置

## 文件放置原则

### 相关文件就近放置

```typescript
// ✅ 好的：组件脚本与预制体在同一目录
ui-panels/
└── main-menu/
    ├── main-menu-panel.ts
    └── main-menu-panel.prefab

// ❌ 坏的：文件分散
scripts/MainMenuPanel.ts
prefabs/main-menu-panel.prefab
```

### 职责清晰

```typescript
// ✅ 好的：职责明确
framework/
├── core/           # 核心基础设施
├── event/          # 事件系统
└── ui/             # UI 框架

// ❌ 坏的：职责混乱
framework/
├── misc/           # 不明确
├── common/         # 太宽泛
└── utils/          # 所有东西都放这里
```

## 目录层级

**建议：2-4 层**

```typescript
// ✅ 好的：层级合理
framework/core/service-locator.ts
ui-panels/battle/skill-panel.ts

// ⚠️ 警告：层级过深
framework/core/service/locator/impl/v1.ts
```

如果层级过深，考虑：
- 扁平化结构
- 合并相关目录
- 重新组织职责

## 演进示例

### 第一阶段：启程（当前）

冒险团刚刚启程，搭好基础设施：

```
assets/
├── squad/                      # 冒险团框架（可复用基础设施）
│   ├── embark.ts               # 框架启程入口
│   ├── squad.ts                # 冒险团（服务容器）
│   ├── assistants/             # 助手们（辅助工具）
│   │   ├── journal.ts          # 记录官（日志系统）
│   │   └── navigator.ts        # 领航员（错误处理工具）
│   ├── crews/                  # 伙伴们（服务实现）
│   │   ├── shadow.ts           # 影子（分身容器）
│   │   ├── shadow-servant.ts   # 影子仆从（分身）
│   │   ├── discipline.ts       # 风纪官（异常捕获）
│   │   ├── beacon.ts           # 信标（数据上报）
│   │   ├── steward.ts          # 管家（数据存储）
│   │   └── contracts/          # 伙伴契约（接口定义）
│   │       ├── crew.ts         # 伙伴基础契约
│   │       ├── shadow.ts       # 影子契约
│   │       ├── discipline.ts   # 风纪官契约
│   │       ├── beacon.ts       # 信标契约
│   │       └── steward.ts      # 管家契约
│   ├── exceptions/             # 异常类
│   │   └── squad-violation-error.ts
│   └── registry/               # 登记簿（常量馆）
│       └── roster.ts           # 伙伴花名册
└── adventure/                  # 冒险游戏（业务逻辑）
    └── bootstrap.ts            # 游戏启动入口
```

**架构分层：**
- **squad** — 框架层，可复用的基础设施
- **adventure** — 业务层，游戏特定的逻辑实现

**核心概念：**
- **squad** — 冒险团，所有伙伴（服务）的家
- **crew** — 伙伴，每个服务都是一个伙伴
- **assistant** — 助手，辅助性工具（如记录官、领航员）
- **embark** — 框架启程，召集框架伙伴
- **bootstrap** — 游戏启程，启动游戏逻辑
- **roster** — 花名册，记录所有伙伴的名字
- **Bind** — 建立羁绊，注册伙伴
- **Link** — 编入队伍，激活伙伴
- **Summon** — 召唤，解析伙伴

**已召集伙伴：**
- **Journal（记录官）** — 日志系统
- **Navigator（领航员）** — 错误处理工具
- **Shadow（影子）** — 事件管理，分身容器
- **Discipline（风纪官）** — 异常捕获
- **Beacon（信标）** — 数据上报
- **Steward（管家）** — 数据存储
