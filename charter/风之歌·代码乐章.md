## 核心原则

> _"简洁胜于机巧，清晰胜于巧妙。"_

1. **代码是写给人看的**，机器能读懂是顺带的
2. **一致性至上**——风格统一比个人喜好更重要
3. **用最简单的方式**表达最清晰的意图

## 基础规范

### 缩进与空白

```typescript
// ✅ 好的：使用 2 个空格缩进
class Hero extends Component {
  update(deltaTime: number) {
    if (this.isAlive) {
      this.move(deltaTime);
    }
  }
}

// ❌ 坏的：使用 Tab 或 4 空格
class Hero extends Component {
      update(deltaTime: number) {
            ...
      }
}
```

### 分号

```typescript
// ✅ 好的：语句结束时加分号
const name = '小柯';
const hero = new Hero();

// ❌ 坏的：省略分号
const name = '小柯';
const hero = new Hero();
```

### 引号

```typescript
// ✅ 好的：普通字符串用单引号，多行或插值用模板字符串
const heroName = '小柯';
const message = `你好，${heroName}！`;

// ❌ 坏的：混用引号
const heroName = '小柯';
```

### 每行长度

```typescript
// ✅ 好的：每行不超过 120 字符
const longMessage = '这是一段很长的文字，我们应该把它拆分成多行以提高可读性';

// ✅ 好的：字符串拼接也遵循此规则
const fullMessage = '第一段文字' + '第二段文字' + '第三段文字';

// ❌ 坏的：一行写得太长
const longMessage = '这是一段很长的文字，如果你一直写下去就会超过一百个字符，这样的话代码就很难阅读了';
```

## 变量与命名

### 声明变量

```typescript
// ✅ 好的：永远使用 const / let
const maxHp = 100;
let currentHp = maxHp;

// ❌ 坏的：绝不使用 var
var maxHp = 100;
```

### 命名规范

```typescript
// ✅ 好的：变量和函数用 camelCase
const heroName = '小柯';
function getHeroById(id: string) {}

// ✅ 好的：类和接口用 PascalCase
class HeroManager {}
interface IHeroConfig {}

// ✅ 好的：常量用 UPPER_SNAKE_CASE
const MAX_LEVEL = 99;
const DEFAULT_HP = 100;

// ✅ 好的：私有成员用下划线前缀
class Hero {
  private _hp: number = 100;

  get hp(): number {
    return this._hp;
  }
}

// ✅ 好的：布尔值用 is/has/can 前缀
const isAlive = true;
const canAttack = false;
const hasWeapon = true;

// ❌ 坏的：无意义的命名
const a = 1;
const temp = '小柯';
const data = getSomething();
```

## 函数

### 函数声明

```typescript
// ✅ 好的：使用命名函数声明
function attack(target: Node): void {
  // ...
}

// ✅ 好的：箭头函数用于简单逻辑
const attack = (target: Node): void => {
  // ...
};

// ❌ 避免：不必要的 function 关键字（在能用箭头函数的地方）
```

### 参数

```typescript
// ✅ 好的：参数不超过 4 个，多的用对象封装
function createHero(
  name: string,
  level: number,
  hp: number,
  mp: number,
) {}

// ✅ 更好的：用配置对象
interface HeroConfig {
  name: string;
  level: number;
  hp: number;
  mp: number;
}

function createHero(config: HeroConfig) {}

// ❌ 坏的：参数太多
function createHero(name, level, hp, mp, atk, def, spd, ...) {}
```

## 类型与接口

### 优先使用 interface

```typescript
// ✅ 好的：定义对象结构用 interface
interface HeroConfig {
  name: string;
  hp: number;
}

// ✅ 好的：简单类型用 type
type HeroID = string;
type HeroState = 'idle' | 'run' | 'attack';

// ❌ 避免：能用 interface 时不用 type 定义对象
```

### 类型推断

```typescript
// ✅ 好的：显式标注函数参数和返回值
function add(a: number, b: number): number {
  return a + b;
}

// ✅ 好的：简单的变量可以依赖推断
const count = 0;
const heroes = [];

// ❌ 避免：复杂的类型不写注解
const data = getSomething(); // 什么类型？
```

## 条件与循环

### 条件判断

```typescript
// ✅ 好的：使用 === 和 !==
if (hero.hp === 0) {
}

// ❌ 坏的：使用 == 和 !=
if (hero.hp == 0) {
}

// ✅ 好的：简写的布尔表达式
if (isAlive) {
}
if (!isAlive) {
}

// ❌ 坏的：冗余的比较
if (isAlive === true) {
}
if (isAlive === false) {
}
```

### 循环

```typescript
// ✅ 好的：使用 for...of 遍历数组
for (const hero of heroes) {
  hero.attack();
}

// ✅ 好的：使用 for...in 遍历对象
for (const key in config) {
  console.log(key, config[key]);
}

// ❌ 避免：传统的 for 循环（除非有特殊需求）
for (let i = 0; i < heroes.length; i++) {
  heroes[i].attack();
}
```

## Cocos Creator 特别规范

### 组件装饰器

```typescript
// ✅ 好的：装饰器紧挨着被装饰的声明，之间不留空行
import { _decorator, Component } from 'cc';
const { ccclass, property } = _decorator;

@ccclass('Hero')
export class Hero extends Component {
  @property({
    type: SpriteFrame,
    tooltip: '英雄头像',
  })
  public avatar: SpriteFrame = null!;

  @property({
    tooltip: '最大生命值',
    min: 1,
    max: 9999,
  })
  public maxHp: number = 100;
}
```

### 生命周期方法

```typescript
// ✅ 好的：按标准顺序排列生命周期方法
@ccclass('Hero')
export class Hero extends Component {
  // 1. @property 装饰的属性

  // 2. 公共成员变量
  public speed: number = 100;

  // 3. 私有成员变量
  private _hp: number = 100;

  // 4. onLoad - 节点加载时调用
  protected onLoad(): void {}

  // 5. start - 组件第一次激活时调用
  protected start(): void {}

  // 6. update - 每帧更新
  protected update(deltaTime: number): void {}

  // 7. lateUpdate - 每帧更新之后
  protected lateUpdate(deltaTime: number): void {}

  // 8. onDestroy - 组件销毁时
  protected onDestroy(): void {}

  // 9. 其他公共方法
  public attack(): void {}

  // 10. 其他私有方法
  private _takeDamage(value: number): void {}
}
```

### 节点查找

```typescript
// ✅ 好的：使用依赖注入，减少运行时查找
@ccclass('Battle')
export class Battle extends Component {
  @property(Hero)
  public hero: Hero = null!;
}

// ✅ 好的：必要时使用 find，但要缓存结果
private _hero: Hero | null = null;

protected onLoad(): void {
  this._hero = this.node.getComponent(Hero);
}

// ❌ 避免：每帧都查找节点
protected update(deltaTime: number): void {
  const hero = this.node.getComponent(Hero); // 性能杀手
}
```

## 注释规范

### 单行注释

```typescript
// ✅ 好的：注释前空一格，注释内容首字母大写
// 这是一个英雄类
class Hero {}

// ❌ 坏的：没有空格，首字母不大写
//这是一个英雄类
class Hero {}
```

### 多行注释

```typescript
// ✅ 好的：使用 JSDoc 风格
/**
 * 英雄类
 * @description 游戏中的可战斗单位
 * @author 小柯
 * @date 2026-04-11
 */
class Hero {}
```

### TODO 注释

```typescript
// ✅ 好的：TODO 后面跟上责任人
// TODO(小亮): 需要优化这段代码的性能
function slowFunction() {}

// ✅ 好的：FIXME 标记需要修复的问题
// FIXME(小柯): 这里有内存泄漏风险
function leakyFunction() {}
```
